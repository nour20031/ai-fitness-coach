# Dataset Card

## Dataset Purpose

This dataset supports the AI-Orchestrated Fitness Coach project. It is intended for evaluating and later training exercise-form analysis models for two exercises: squat and bicep curl.

The dataset is not intended for medical diagnosis, injury assessment, rehabilitation advice, or professional training certification.

## Exercises Included

- Squat
- Bicep curl

## Labels

The current source folders were manually reviewed before processing and are treated as the verified ground-truth class for the videos they contain. Each segmented repetition inherits the label of its source video. Segmentation and form analysis are still separate tasks: segmentation finds repetition boundaries, while future classifiers will learn to predict the verified form label.

Allowed squat labels:

- `correct`: full/deep squat.
- `shallow`: incomplete-depth squat.

Allowed bicep curl labels:

- `correct`: full-range bicep curl.
- `half_range`: incomplete range-of-motion bicep curl.

The word `incorrect` is avoided as a final class label because the collected incomplete-form examples represent specific, controlled issues rather than arbitrary unsafe exercise form.

## Source Filename Metadata

The current source videos use anonymous metadata encoded in the filename:

```text
vidXX_idXX_front.mp4
vidXX_idXX_side.mp4
```

- `vidXX` = unique source-video ID.
- `idXX` = anonymous participant ID.
- `front` or `side` = camera viewpoint.

The parser converts `id1` to `participant01`, `id2` to `participant02`, and so on. The original renamed source files are preserved in `dataset/external/workoutfitness-video/`. Canonical copies are created under `dataset/raw/`.

## Viewpoints

The planned viewpoints are:

- Front
- Side

Viewpoint is now parsed from the authoritative source filename. It is not inferred from image content.

## Source Video Length

From the current manifest:

- Source videos: 23
- Average duration: 23.08 seconds
- Minimum duration: 6.81 seconds
- Maximum duration: 39.0 seconds

Most videos were intended to contain repeated exercise sets, commonly around 10 repetitions. The current validation reports compare detected repetitions against this expected count and flag videos that need segmentation review.

## Collection Procedure

Videos were recorded from adult volunteers for this university project. Recording instructions included:

- stationary camera
- full body visible for squats
- shoulders, elbows, and wrists visible for bicep curls
- approximately one-second pause between repetitions where possible
- front and side recordings where possible

## Consent And Ethics

Volunteers gave consent for their exercise videos to be used for this academic project. Raw videos are treated as private participant data and should not be committed to a public repository.

## Safety Considerations

The incomplete-form videos should use controlled incomplete movements rather than dangerous movements. For example:

- shallow squat depth
- half-range bicep curl

The dataset should not require volunteers to perform intentionally harmful or risky movement patterns.

## Storage And Privacy

Raw videos, derived clips, augmented videos, and local manifests containing original filenames/paths are private project data. They are excluded from public Git tracking by `.gitignore`.

Processed non-identifying numerical features may be considered for sharing later if this is consistent with consent and university ethics guidance.

## Train/Validation/Test Splitting Strategy

The intended strategy is participant-level splitting:

- training: approximately 70%
- validation: approximately 15%
- test: approximately 15%

The previous split files were created before participant IDs were parsed and are now obsolete. Because the dataset currently has only four participants, a simple random 70/15/15 split is not defensible for final evaluation. The current Phase 1 plan uses Leave-One-Participant-Out evaluation so that all videos and clips from one participant remain together.

Current limitation: `participant04` only contributes squat shallow videos, so the participant-level folds are useful for leakage control but still class-imbalanced.

## Augmentation Strategy

Augmentation is applied only to training data. Validation and test data must never be augmented.

Allowed conservative transformations include:

- small brightness changes
- small contrast changes
- slight crop/zoom
- small rotation
- horizontal flip where biomechanically valid

Transformations must not change the exercise label or alter a correct movement into an incomplete movement.

Earlier augmentation outputs are marked obsolete/provisional because final augmentation must happen only after segmentation validation and the final participant-level evaluation strategy.

## Known Missing Metadata Or Data

- No participant/view metadata rows are currently missing from the manifest.
- `participant04_squat_shallow_front_set01.mp4` is flagged by the quality audit for possible zero or low movement.
- Several source videos still require segmentation review because the detected repetition count differs from the expected count by more than one repetition.
- Demographic metadata is not included and should not be added unless explicitly approved by ethics guidance and consent.

## Limitations

- Current dataset size is still small.
- Current videos may be biased toward a limited set of volunteers, cameras, rooms, lighting conditions, and body types.
- The current dataset is participant-limited and class-imbalanced across participants.
- Segmentation validation currently detects 187 of 230 expected repetitions, so segmentation review and further refinement are still needed before model comparison.
- Exercise-form classification must later be evaluated against the verified source labels inherited by clips, not against rule-based analyser outputs.
- The old unknown-metadata system has been replaced by automated parsing from `vidXX_idXX_front/side` filenames.
